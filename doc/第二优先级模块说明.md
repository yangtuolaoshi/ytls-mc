# 第二优先级模块说明

本文描述第二优先级已落地模块的设计、API 与扩展方式。对应需求文档 **10.2 第二优先级**。

## 1. 组件系统

### 目标

为玩家、实体、方块实体、维度提供统一附加数据，业务层不直接接触 Forge Capability。

### 核心类

| 类 | 职责 |
|----|------|
| `@RegisterComponent` | 声明可扫描注册的组件类型 |
| `ComponentRegistry` | 类型注册表 |
| `ComponentAccess` | 业务访问入口 |
| `ForgeComponentHolder` | 内部 NBT 持久化容器 |
| `ComponentCapabilities` | Forge Capability 绑定 |

### 挂载目标

- `Entity` / `Player`：死亡重生时自动 `copyFrom`
- `BlockEntity`
- `Level`（维度级状态）

### 业务示例

`gameplay/component/PlayerStatsComponent.java`

```java
@RegisterComponent(value = "player_stats", targets = {ComponentTarget.PLAYER})
public final class PlayerStatsComponent implements GameComponent {
    public static ComponentType<PlayerStatsComponent> type() {
        return ComponentRegistry.type("player_stats");
    }
    // save / load / copyFrom ...
}
```

访问：

```java
PlayerStatsComponent stats = ComponentAccess.getOrCreate(player, PlayerStatsComponent.type());
```

## 2. AI 框架

### 目标

在原版 Goal 之上提供可组合的行为树式节点，减少手写 Goal 类。

### 核心类

| 类 | 职责 |
|----|------|
| `BehaviorNode` | 行为节点接口 |
| `SequenceBehavior` | 顺序执行（全部可执行才执行） |
| `SelectorBehavior` | 选择执行（第一个可执行节点） |
| `LeafBehavior` | 叶子节点（条件 + 动作） |
| `BehaviorGoal` | 包装为原版 `Goal` |
| `AiManager` | 注册/应用 AI 配置 |

### 用法

```java
AiManager.register("my_profile", new SelectorBehavior(List.of(
    new LeafBehavior(ctx -> ctx.target() != null, ctx -> ctx.mob().getNavigation().moveTo(ctx.target(), 1.0D))
)), 2);

// 实体生成后
AiManager.apply(mob, "my_profile");
```

示例：`gameplay/common/ExampleSecondPrioritySetup.java`

## 3. 技能框架

### 目标

统一建模技能施法、冷却、阶段；服务端判定 + 客户端表现分离。

### 核心类

| 类 | 职责 |
|----|------|
| `@RegisterSkill` | 扫描注册技能 |
| `Skill` | 技能接口（冷却、阶段回调） |
| `SkillRegistry` | 技能注册表 |
| `SkillCaster` | 施法/冷却/tick 管理 |
| `SkillStateComponent` | 技能状态组件（持久化 + 同步） |

### 技能接口

```java
@RegisterSkill("my_skill")
public class MySkill implements Skill {
    public ResourceLocation id() { return ModResources.loc("my_skill"); }
    public int cooldownTicks() { return 60; }
    public int castTicks() { return 20; }
    public boolean canCast(SkillContext ctx) { ... }
    public void onCastStart(SkillContext ctx) { ... }
    public void onCastTick(SkillContext ctx) { ... }
    public void onCastEnd(SkillContext ctx) { ... }
}
```

施法：

```java
SkillCaster.tryCast(livingEntity, "my_skill");
```

框架会在 `LivingTickEvent` 中自动 tick 施法进度。

客户端表现请通过 `PresentationEmitter` 触发，不要在 `Skill` 内直接调用客户端 API。

### 业务示例

`gameplay/skill/ExampleSlashSkill.java`

## 4. 世界规则系统

### 目标

将维度级玩法封装为可启停、有优先级的规则。

### 核心类

| 类 | 职责 |
|----|------|
| `@RegisterWorldRule` | 扫描注册规则 |
| `WorldRule` | 规则接口 |
| `RuleScope` | 作用域（GLOBAL / DIMENSION / BIOME / REGION） |
| `WorldRuleEngine` | 注册、启停、按优先级 tick |

### 用法

```java
@RegisterWorldRule(value = "blood_moon", priority = 100)
public class BloodMoonRule implements WorldRule {
  public void onTick(RuleContext context) { ... }
}
```

运行时开关：

```java
WorldRuleEngine.setEnabled("blood_moon", false);
```

框架在 `LevelTickEvent`（END，服务端）自动驱动规则 tick。

### 业务示例

`gameplay/worldrule/ExampleBloodMoonRule.java`

## 5. 客户端表现封装

### 目标

服务端业务通过统一接口触发粒子、音效、ActionBar，客户端代码集中在框架层。

### 核心类

| 类 | 职责 |
|----|------|
| `PresentationEmitter` | 服务端发送表现请求 |
| `ClientPresentationMessage` | 网络消息（TO_CLIENT） |
| `ClientPresentationHandler` | 客户端执行表现 |
| `PresentationType` | PARTICLE / SOUND / ACTION_BAR |

### 用法（仅服务端）

```java
PresentationEmitter.actionBar(serverPlayer, "技能释放！");
PresentationEmitter.sound(serverPlayer, "minecraft:entity.player.attack.sweep", 1.0F, 1.0F);
PresentationEmitter.particle(serverLevel, pos, "happy_villager");
```

资源不存在时客户端会降级（跳过音效等）并输出 warn 日志。

## 6. 与第一优先级的衔接

| 第一优先级 | 第二优先级如何使用 |
|-----------|-------------------|
| 网络体系 | `ClientPresentationMessage`、`EntitySyncMessage` |
| 同步体系 | 组件字段 `@SyncField`，`SyncHelper.markDirty` |
| 事件体系 | 可在 `@Listen` 中调用 `SkillCaster` / `WorldRuleEngine` |
| 调试体系 | 扩展 `/ytls skill`、`/ytls rule`、`/ytls component` 命令 |
