# 框架测试指南

本文提供 **第一优先级** 与 **第二优先级** 框架能力的自主测试步骤。请在本地执行，无需自动化测试脚本。

> 环境：Minecraft **1.20.4** + Forge **49.2.7**  
> 模组 ID：`ytls`

---

## 0. 测试前准备

### 0.1 编译

```bash
gradlew compileJava
```

预期：BUILD SUCCESSFUL，无 error（deprecated 警告可忽略）。

### 0.2 启动客户端

```bash
gradlew runClient
```

预期：进入主菜单/世界，无 crash。

### 0.3 开启调试能力

开发环境（非 production）下调试命令自动可用。若需在生产配置下测试，编辑 `run/config/ytls-framework.toml`：

```toml
[debug]
enabled = true
```

### 0.4 日志前缀

框架日志格式：`[ytls|framework|模块名]`。测试时可过滤关键字 `ytls` 或 `framework`。

## 1. 第一优先级测试

### 1.1 启动与生命周期

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 启动游戏，观察控制台 | 出现 `Initializing YTLS framework`、`Framework initialized` |
| 2 | 创建/进入世界 | 出现 `Example gameplay common setup complete` |
| 3 | 进入世界后观察 | 出现 `World loaded: minecraft:overworld`（`@OnLifecycle(WORLD_LOAD)`） |
| 4 | 全程 | 无 `Lifecycle handler failed` 异常 |

### 1.2 注册体系

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 启动时查看日志 | 出现 `Registered BLOCK -> ytls:example_block`、`Registered ITEM -> ytls:example_ingot`、`Registered SOUND -> ytls:example_chime` |
| 2 | 游戏中 OP 权限执行 `/ytls registry` | 聊天栏按类型统计（BLOCK/ITEM/SOUND 等）≥ 3 条 |
| 3 | 创造模式搜索 | 能找到示例方块/物品（名称由 datagen/lang 决定） |

**可选：数据生成**

1. 准备贴图 `src/main/resources/assets/ytls/textures/block/example_block.png`
2. 执行 `gradlew runData`
3. 检查 `src/generated/resources/` 下是否生成 lang、model、blockstate、loot_table、recipe、tags

### 1.3 事件体系

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 进入单人世界 | 控制台出现 `Player login: <玩家名>` |
| 2 | 破坏/放置示例方块 | 无 crash（`BLOCK_BREAK` / `BLOCK_PLACE` 已桥接） |
| 3 | 右键空气持物品 | 无 crash（`ITEM_USE` 已桥接） |
| 4 | 退出世界 | 无异常（登出事件已注册桥接） |

> 可在 `ytls-framework.toml` 设置 `logEvents = true` 查看事件 debug 日志。

### 1.4 网络体系

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 启动日志 | 出现 `Registered network message 'ping'`、`entity_sync`、`client_presentation` |
| 2 | 打开 LAN 或多人（可选） | 客户端/服务端连接正常，无 channel 版本拒绝 |

> 示例 `PingMessage` 为 TO_SERVER 消息，可通过业务代码从客户端发送；当前示例未默认绑定按键，以日志注册为验收。

### 1.5 配置体系

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 首次进入世界 | `run/config/` 生成 `ytls-framework.toml`、`ytls-gameplay.toml` |
| 2 | 修改 `ytls-gameplay.toml` 中 `exampleValue` | 文件格式正确，游戏可正常启动 |
| 3 | 执行 `/ytls reload-config` | 提示重载方式，无 crash |

### 1.6 资源生成

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 执行 `gradlew runData`（需贴图） | `src/generated/resources` 有输出 |
| 2 | 再次 `runClient` | 示例物品/方块模型、中文名正常 |

### 1.7 调试体系

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | `/ytls debug` | 返回 `YTLS debug mode active` |
| 2 | `/ytls registry` | 按 RegistryKind 分类显示注册数量 |
| 3 | `/ytls component stats` 多次 | 数值递增且提示 `(synced)` |
| 4 | 无 OP 权限账号执行 | 命令不可用（权限不足） |

## 2. 第二优先级测试

### 2.1 组件系统

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 启动日志 | 出现 `Registered component type: ytls:player_stats`、`ytls:skill_state` |
| 2 | OP 执行 `/ytls component stats` 多次 | 聊天栏 `player_stats.exampleValue` 递增并显示 `(synced)` |
| 3 | 退出并重新进入世界 | 组件值按 Capability NBT 持久化（若未清空玩家数据） |
| 4 | 玩家死亡重生 | 组件通过 `PlayerEvent.Clone` 复制，无 crash |

### 2.2 AI 框架

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 启动日志 | 出现 `Registered example AI profile: example_aggressive` |
| 2 | 在代码或临时命令中对僵尸调用 `AiManager.apply(zombie, "example_aggressive")` | 僵尸在有目标时会追击/攻击 |
| 3 | 观察行为 | 无 crash，Goal 正常 tick |

**建议测试方式（创造模式 + 命令）：**

1. `/summon zombie ~ ~ ~`
2. 在开发中可临时于 `ExampleGameplaySetup` 中对附近 Mob 调用 `AiManager.apply`；或通过 IDE 断点验证

> 后续可在业务分支增加 `@Listen` + 生成事件自动 apply，本指南以框架 API 可调用为验收。

### 2.3 技能框架

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 启动日志 | 出现 `Registered skill: ytls:example_slash` |
| 2 | OP 执行 `/ytls skill cast example_slash` | 返回 `Skill cast started` |
| 3 | 观察客户端 | ActionBar 显示「示例斩击 · 蓄力/完成」 |
| 4 | 观察客户端 | 播放 sweep 音效、粒子效果 |
| 5 | 冷却期间再次 cast | 返回 `Skill cast failed` |
| 6 | 等待约 2 秒后再 cast | 可再次施法 |

### 2.4 世界规则

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 启动日志 | 出现 `Registered world rule: example_blood_moon` |
| 2 | 进入世界等待约 60 秒（1200 tick） | 控制台周期性出现 `[BloodMoon Demo] world tick at ...` |
| 3 | `/ytls rule toggle example_blood_moon` | 提示 `disabled` |
| 4 | 再等待 60 秒 | 不再输出 BloodMoon 日志 |
| 5 | 再次 toggle 启用 | 日志恢复 |

### 2.5 客户端表现

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 施放 `example_slash` 技能 | 见 2.3 表现效果 |
| 2 | 使用错误音效 ID（可自行临时代码测试） | 客户端 warn 日志，游戏不 crash |

## 3. 回归检查清单

完成全部测试后，确认以下项：

- [ ] 编译无 error
- [ ] 客户端可进入世界
- [ ] 无 `Lifecycle handler failed`
- [ ] 示例方块/物品/音效可注册
- [ ] `/ytls registry` 按类型统计
- [ ] `/ytls` 调试命令可用
- [ ] 玩家登录与世界加载日志正常
- [ ] 配置文件自动生成
- [ ] runData 生成 loot/recipe/tags
- [ ] 组件命令可递增 stats
- [ ] 技能 cast 有表现与冷却
- [ ] 世界规则可 toggle
- [ ] AI profile 注册成功

## 4. 常见问题

### Q: `/ytls` 命令不存在？

- 确认 `DevEnvironment.isDebugActive()` 为 true（开发环境或 `ytls-framework.toml` 中 `debug.enabled=true`）
- 确认有 OP 权限等级 2

### Q: 示例方块紫黑块？

- 缺少贴图或未完成 `runData`，见 1.2 可选步骤

### Q: 技能 cast 成功但无表现？

- 检查是否为服务端执行命令（单人游戏集成服务端即可）
- 检查日志是否有 `client_presentation` 注册

### Q: 组件 stats 重启后归零？

- 检查是否删除了 `run/saves` 玩家数据；组件 NBT 随玩家 Capability 保存
