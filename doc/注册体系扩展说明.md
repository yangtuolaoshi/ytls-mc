# 注册体系扩展说明

本文说明 YTLS 框架 **12 类 `RegistryKind`** 的注解驱动方式，以及**不宜仅用注解**、需通过 `RegistryContributor` 或数据包扩展的场景。

> 目标版本：Minecraft **1.20.4** + Forge **49.2.7**

---

## 1. 十二类注册一览

| RegistryKind | 专用注解 | 注册模式 | 说明 |
|--------------|----------|----------|------|
| `BLOCK` | `@RegisterBlock` | 无参构造 | 继承 `Block` |
| `ITEM` | `@RegisterItem` | 无参构造 | 继承 `Item` |
| `SOUND` | `@RegisterSound` | `RegistrySupplier` | 音效事件 |
| `ENTITY` | `@RegisterEntity` | `RegistrySupplier` | `EntityType` |
| `BLOCK_ENTITY` | `@RegisterBlockEntity` | `RegistrySupplier` | 常依赖已注册方块，见 §3 |
| `MENU` | `@RegisterMenu` | `RegistrySupplier` | 需配合 Screen，见 §4 |
| `MOB_EFFECT` | `@RegisterMobEffect` | `RegistrySupplier` | 状态效果 |
| `PARTICLE` | `@RegisterParticle` | `RegistrySupplier` | 粒子类型 |
| `ENCHANTMENT` | `@RegisterEnchantment` | `RegistrySupplier` | 附魔，见 §4 |
| `ATTRIBUTE` | `@RegisterAttribute` | `RegistrySupplier` | 属性，需挂到实体 |
| `CREATIVE_TAB` | `@RegisterCreativeTab` | `RegistrySupplier` | 创造模式物品栏 |
| `RECIPE_SERIALIZER` | `@RegisterRecipeSerializer` | `RegistrySupplier` | 自定义配方类型，见 §4 |

兜底：任意类型仍可使用 `@RegisterEntry(kind = ..., value = "...")`。

---

## 2. 扫描顺序与依赖

`RegistryScanner` 按 `RegistryKind.scanOrder()` 分阶段扫描：

1. **0**：`BLOCK`、`ITEM`
2. **10**：音效、实体、效果、粒子、附魔、属性、菜单、配方序列化器、创造栏
3. **20**：`BLOCK_ENTITY`（可在 Supplier 内安全调用 `RegistryAccess.block(...)`）
4. **最后**：`RegistryContributor` 实现类

若出现「Supplier 内条目为 null」，请检查是否引用了尚未注册的名称，或改在 `RegistryContributor` 中注册。

## 3. 方块实体（BLOCK_ENTITY）

### 方式 A：注解 + Supplier

```java
@RegisterBlockEntity("my_be")
public final class MyBlockEntitySupplier implements RegistrySupplier<BlockEntityType<?>> {
    @Override
    public BlockEntityType<?> get() {
        AtomicReference<BlockEntityType<MyBlockEntity>> ref = new AtomicReference<>();
        BlockEntityType<MyBlockEntity> type = BlockEntityType.Builder.of(
                (pos, state) -> new MyBlockEntity(ref.get(), pos, state),
                RegistryAccess.block("my_block").defaultBlockState()
        ).build(null);
        ref.set(type);
        return type;
    }
}
```

### 方式 B：RegistryContributor（推荐复杂场景）

见 `gameplay/registry/ExampleGameplayRegistryContributor.java`。

## 4. 建议用 Contributor / 文档示例的类型

以下类型**已提供专用注解**，但因与 Screen、数据包或全局注册强耦合，**不建议在创意分支首版硬写注解类**，请参考模板后按需实现。

### 4.1 菜单（MENU）

```java
// 在 RegistryContributor.contribute 中：
registry.register(RegistryKind.MENU, "my_menu", () ->
        IForgeMenuType.create((windowId, inv, data) -> new MyMenu(windowId, inv)));
```

还需：注册 `MenuScreen`（`@OnLifecycle(CLIENT_SETUP)`）、网络打开容器等。

### 4.2 附魔（ENCHANTMENT）

```java
registry.register(RegistryKind.ENCHANTMENT, "my_enchant", () -> new Enchantment(
        Enchantment.Rarity.RARE,
        EnchantmentCategory.WEAPON,
        EquipmentSlot.MAINHAND) {
    @Override
    public int getMinLevel() { return 1; }
    @Override
    public int getMaxLevel() { return 3; }
    // ... 实现其余抽象方法
});
```

### 4.3 配方序列化器（RECIPE_SERIALIZER）

```java
registry.register(RegistryKind.RECIPE_SERIALIZER, "my_shapeless", () ->
        new SimpleRecipeSerializer<>(MyShapelessRecipe::new));
```

并配合 `RecipeType`、datagen 或 JSON 数据包。

## 5. 不宜纳入 12 类 RegistryKind 的扩展（验收文档「未覆盖」项）

下列能力属于 **Forge / 数据包 / Codec** 体系，**不强行塞入 DeferredRegister 封装**，请使用 `RegistryContributor` 或在 `COMMON_SETUP` 中注册：

| 能力 | 推荐方式 |
|------|----------|
| 结构（Structure）、地物（Feature）、矿脉 | `DeferredRegister` 创建在 Contributor 中；或数据包 JSON + 事件 |
| 战利品条件/函数扩展 | `GlobalLootModifier` / 数据包 `loot_table` |
| `Codec` / `MapCodec` 自定义数据类型 | `RegisterEvent` 注册 DataComponent 或自定义 Registry |
| 维度/生物群系 | 数据包 + Forge 事件 |

示例 Contributor 骨架：

```java
public final class MyWorldGenContributor implements RegistryContributor {
    @Override
    public void contribute(RegistryFacade registry) {
        // registry 参数用于 BLOCK/ITEM 等框架类型；
        // 世界生成请在此获取 Mod 的 DeferredRegister 并 register(bus)，
        // 或仅在 @OnLifecycle(COMMON_SETUP) 中向 Forge 注册。
    }
}
```

## 6. 访问与错误提示

```java
Block block = RegistryAccess.block("my_block");
Item item = RegistryAccess.item("my_ingot");
// 任意类型：
EntityType<?> mob = RegistryAccess.resolve(RegistryKind.ENTITY, "my_mob");
```

未注册时抛出 `IllegalStateException`，消息中包含 `kind/name` 并提示添加 `@Register*` 或 `RegistryContributor`。

重复注册同名条目会在**扫描阶段**立即失败（不静默）。

---

## 7. 客户端 / 服务端

所有 `DeferredRegister` 条目在 Mod 构造期绑定到 Mod Event Bus，**逻辑注册在双端一致**；仅客户端生效的行为（渲染、Screen）应放在 `@OnLifecycle(CLIENT_SETUP)`，不要放在注册 Supplier 内直接调用客户端类。

---

## 8. 与数据生成联动

`ForgeRegistryProvider.catalog()` 驱动：

- `BLOCK` / `ITEM`：lang、model、blockstate、loot、recipe、tags
- `CREATIVE_TAB`：lang（`itemGroup.<modId>.<name>`）

其余类型若需 lang，请在 `RegistryContributor` 中自行维护或扩展 Provider。
