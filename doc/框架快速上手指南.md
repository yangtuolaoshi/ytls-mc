# YTLS 框架快速上手指南

本文面向从主分支拉取创意 Mod 分支的开发者，帮助你在 **不写 Forge 底层样板代码** 的前提下快速接入方块、物品、事件、网络、配置与资源生成。

> 目标版本：Minecraft **1.20.4** + Forge **49.2.7**  
> 模组 ID：`ytls`  
> 业务代码包：`icu.ytlsnb.ytls.gameplay`

---

## 1. 项目结构

```text
src/main/java/icu/ytlsnb/ytls/
├── YtlsMod.java              # 极薄入口，仅调用 Framework.initialize()
├── ModConstants.java         # MOD_ID 等常量
├── framework/                # 【主分支维护】框架层，业务分支不要改
│   ├── bootstrap/            # 启动、生命周期
│   ├── registry/             # 注册体系
│   ├── event/                # 语义化事件
│   ├── network/              # 网络消息
│   ├── sync/                 # 字段同步
│   ├── config/               # 配置
│   ├── data/                 # 数据生成
│   └── debug/                # 调试命令与开关
└── gameplay/                 # 【创意分支编写】你的玩法代码放这里
    ├── block/
    ├── item/
    ├── network/
    ├── config/
    └── common/
```

**原则：**

- 框架层封装 Forge 细节（`DeferredRegister`、`FriendlyByteBuf`、原始 EventBus 等）
- 业务层只写玩法，通过注解 + 约定接入框架
- 换 Minecraft/Forge 版本时，优先改 `framework` 下的 Forge 实现，业务层尽量不动

## 2. 5 分钟接入一个新物品

### 步骤 1：创建物品类

```java
package icu.ytlsnb.ytls.gameplay.item;

import icu.ytlsnb.ytls.framework.registry.annotation.RegisterItem;
import net.minecraft.world.item.Item;

@RegisterItem("my_ingot")
public class MyIngotItem extends Item {
    public MyIngotItem() {
        super(new Item.Properties());
    }
}
```

### 步骤 2：完成

无需手动写 `DeferredRegister`。框架启动时会扫描 `gameplay` 包，自动注册并在数据生成时补全 lang / item model。

### 步骤 3（可选）：运行数据生成

```bash
gradlew runData
```

生成结果输出到 `src/generated/resources/`，已加入 Gradle 资源目录。

## 3. 接入一个新方块

```java
package icu.ytlsnb.ytls.gameplay.block;

import icu.ytlsnb.ytls.framework.registry.annotation.RegisterBlock;
import net.minecraft.world.level.block.Block;
import net.minecraft.world.level.block.state.BlockBehaviour;

@RegisterBlock("my_block")
public class MyBlock extends Block {
    public MyBlock() {
        super(BlockBehaviour.Properties.of().strength(2.0F, 6.0F));
    }
}
```

**纹理：** 将方块贴图放到：

```text
src/main/resources/assets/ytls/textures/block/my_block.png
```

然后执行 `gradlew runData` 生成 blockstate 与 model。

## 4. 复杂注册（实体、创造标签等）

简单方块/物品用注解即可。实体类型、创造标签等较复杂的注册，实现 `RegistryContributor`：

```java
public class MyRegistryContributor implements RegistryContributor {
    @Override
    public void contribute(RegistryFacade registry) {
        registry.register(RegistryKind.ENTITY, "my_mob", () -> EntityType.Builder
                .of(MyMob::new, MobCategory.CREATURE)
                .sized(0.6F, 1.8F)
                .build("my_mob"));
    }
}
```

类需有 **无参 public 构造函数**，框架会自动实例化并调用。

注册完成后，业务层通过 `RegistryAccess` 获取实例：

```java
Block block = RegistryAccess.block("my_block");
Item item = RegistryAccess.item("my_ingot");
```

## 5. 生命周期回调

在 `gameplay` 包下任意类中声明 **static** 方法：

```java
import icu.ytlsnb.ytls.framework.bootstrap.LifecyclePhase;
import icu.ytlsnb.ytls.framework.bootstrap.annotation.OnLifecycle;

public class MySetup {
    @OnLifecycle(LifecyclePhase.COMMON_SETUP)
    public static void onCommonSetup() {
        // 通用逻辑初始化
    }

    @OnLifecycle(LifecyclePhase.CLIENT_SETUP)
    public static void onClientSetup() {
        // 客户端初始化（注册渲染器等）
    }
}
```

可用阶段：`CONSTRUCT`、`COMMON_SETUP`、`CLIENT_SETUP`、`SERVER_STARTING`、`SERVER_STARTED`、`SERVER_STOPPING`。

## 6. 语义化事件

框架将 Forge 原始事件桥接为业务可读事件。订阅方式：

```java
import icu.ytlsnb.ytls.framework.event.annotation.Listen;
import icu.ytlsnb.ytls.framework.event.api.GameEventType;
import icu.ytlsnb.ytls.framework.event.events.PlayerLoginEvent;

public class MyEvents {
    @Listen(GameEventType.PLAYER_LOGIN)
    public static void onLogin(PlayerLoginEvent event) {
        var player = event.player();
        // ...
    }
}
```

当前已桥接：`PLAYER_LOGIN`、`PLAYER_LOGOUT`。更多事件类型在 `GameEventType` 枚举中扩展，并在 `ForgeEventBridge` 增加桥接即可。

## 7. 网络消息

定义消息类（**public 字段** + 无参构造）：

```java
@NetworkMessage(id = "my_action", direction = NetworkDirection.TO_SERVER)
public class MyActionMessage extends NetworkPayload {
    public String action = "";

    @Override
    public void handleServer(NetworkContext ctx) {
        ctx.enqueueWork(() -> {
            // 服务端处理，ctx.sender() 为发送玩家
        });
    }
}
```

发送：

```java
// 客户端 -> 服务端
NetworkAccess.channel().sendToServer(new MyActionMessage());

// 服务端 -> 某玩家
NetworkAccess.channel().sendToPlayer(message, serverPlayer);
```

**支持自动编解码的字段类型：** `String`、`int`、`long`、`boolean`、`float`、`double`、`ResourceLocation`、`BlockPos`、`Map<String,String>`。

## 8. 配置

```java
@ModConfig(scope = ConfigScope.COMMON, file = "my-gameplay.toml")
public class MyConfig {
    public static final ForgeConfigSpec SPEC;
    public static final ForgeConfigSpec.ConfigValue<Integer> SPAWN_RATE;

    static {
        ConfigBuilder b = ConfigBuilder.create("My Gameplay Config");
        b.push("spawn");
        SPAWN_RATE = b.define("rate", 10, 1, 100);
        b.pop();
        SPEC = b.build();
    }
}
```

配置文件生成在 `run/config/` 下。框架调试配置见 `run/config/ytls-framework.toml`。

## 9. 调试

开发环境（非 production）下自动启用调试命令。生产环境需在 `ytls-framework.toml` 中设置：

```toml
[debug]
enabled = true
```

可用命令（需 OP 权限 2）：

| 命令 | 说明 |
|------|------|
| `/ytls debug` | 确认调试模式 |
| `/ytls registry` | 查看已注册条目数量 |
| `/ytls reload-config` | 提示配置重载方式 |

日志统一前缀：`[ytls|framework|模块名]`。

## 10. 创意分支工作流

1. 从主分支 `git checkout -b feature/my-idea`
2. **只改** `gameplay/` 下的代码与 `assets/ytls/` 资源
3. 不要复制框架代码到业务分支
4. 需要联动时，将通用能力提取回主分支 `framework/`
5. 废弃分支直接删除，不影响主分支框架完整性

## 12. 常见问题

### Q: 注册没生效？

检查：类是否在 `icu.ytlsnb.ytls.gameplay` 包下；注解 registry 名是否小写+下划线；类是否有 public 无参构造。

### Q: 数据生成报错缺纹理？

先手动放置 `assets/ytls/textures/block/<name>.png`，或暂时注释掉对应 `@RegisterBlock`。

### Q: 能否在业务层直接用 DeferredRegister？

不建议。会绕开框架统一命名、数据生成与版本抽象，增加分支合并成本。
