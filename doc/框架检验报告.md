## 一、总体结论

框架已按设计完成 **第一优先级 8 个子系统** 与 **第二优先级 5 个子系统** 的主体落地，`framework` 与 `gameplay` 包物理隔离，`YtlsMod` 仅调用 `Framework.initialize()`，业务示例层几乎不直接依赖 Forge API（`gameplay` 中仅 `GameplayConfig` 引用 `ForgeConfigSpec` 类型）。

对照《框架验收要求》的分级标准（L1 基础可用 / L2 框架化可用 / L3 生产可用），综合评定如下：

| 维度 | 评定 | 说明 |
|------|------|------|
| 覆盖性 | **L2−** | 核心扩展点有统一入口，但注册类型、语义事件、datagen、网络校验等未达验收文档“至少要测”的全量清单 |
| 抽象有效性 | **L2** | 注册、事件、网络、组件、技能等可通过注解与静态 API 接入；复杂注册、未桥接事件、渲染高级能力仍需触底层 |
| 稳定性 | **L2−** | 启动期 fail-fast 较好；存在语义事件未桥接、粒子占位等可导致“静默不生效”的问题 |
| 可复用性 | **L2** | 分支可复制 `gameplay` 模式快速起步；示例与调试命令有一定耦合 |
| 可维护性 | **L2** | 版本抽象思路清晰（Forge 实现集中在 Provider/Bridge 层）；框架层不宜反向依赖 gameplay |

**综合结论：有条件通过（第一、第二优先级范围内）。**

框架可作为创意 Mod 的 **通用开发底座（L2）** 投入使用，但尚不宜宣称在多人、重载、全量注册覆盖等场景达到 **L3 生产可用**。建议在修复下文 **P0/P1** 缺陷并完成《框架测试指南》运行时回归后，再对外宣布验收闭环。

## 三、第一优先级检验明细

### 3.1 启动与基础框架（需求 6.2 / 验收 §2 生命周期）

| 检验项 | 要求摘要 | 实现情况 | 级别 |
|--------|----------|----------|------|
| 统一入口 | Mod 主类零业务 | `YtlsMod` → `Framework.initialize()` | L2 |
| 生命周期阶段 | common/client/datagen/server/world/config/resource/shutdown | `LifecyclePhase` + `LifecycleManager` + `FrameworkReloadBridge` | L2 |
| 语义化回调 | `@OnLifecycle` 扫描 | 扫描 `gameplay` 包，静态方法校验 | L2 |
| 客户端隔离 | 客户端代码不误跑服务端 | `CLIENT_SETUP` 绑定 `Dist.CLIENT`；网络方向枚举 | L2 |
| 失败可观测 | 阶段失败明确报错 | handler 异常包装为 `IllegalStateException` | L2 |
| Shutdown 清理 | shutdown/cleanup | `SHUTDOWN` 阶段 + `LifecycleCleanupRegistry` + `Framework.registerCleanup` | L2 |

**说明（2026-05-27 优化后）**：世界加载支持 `@OnLifecycle(WORLD_LOAD)` 与 `@Listen(LEVEL_LOAD)` 双入口；`ForgeEventBridge` 已桥接 `LEVEL_LOAD` / `LEVEL_UNLOAD`。

### 3.2 注册体系（需求 6.1 / 验收 §2.1）

| 检验项 | 要求摘要 | 实现情况 | 级别 |
|--------|----------|----------|------|
| 十二类注解驱动 | 各 RegistryKind 专用注解 | `@RegisterBlock` … `@RegisterRecipeSerializer` + `RegistryAnnotationRules` | L2 |
| 方块/物品 | 无参构造 | `@RegisterBlock` / `@RegisterItem` | L2 |
| 音效/实体/效果/粒子/属性/创造栏 | Supplier | 专用注解 + gameplay 示例 Supplier | L2 |
| 方块实体/菜单/附魔/配方序列化器 | Supplier 或 Contributor | 注解已支持；BE 示例用 `RegistryContributor`；菜单/附魔/配方见扩展文档 | L2 |
| 批量注册 | Contributor | `RegistryContributor` + 扫描顺序在注解之后 | L2 |
| 资源关联 | 自动补全 | catalog 驱动 datagen；CREATIVE_TAB lang | L2 |
| 注册顺序 | 依赖顺序 | `RegistryKind.scanOrder()` 分阶段扫描 | L2 |
| 重复/缺失报错 | 不静默 | 重复抛异常；`RegistryAccess` 缺失提示 | L2 |
| 客户端/服务端 | 双端注册、客户端逻辑分离 | 文档 + `CLIENT_SETUP` 约定 | L2 |
| 世界生成/战利品扩展/Codec | 验收列举 | **文档化**： [注册体系扩展说明.md](./注册体系扩展说明.md) | L2（文档） |

**说明（2026-05-27 优化后）**：结构/地物/战利品修饰/Codec 等不强行纳入 DeferredRegister，由扩展文档与 `RegistryContributor` 约定承接，避免错误抽象。

## 七、错误质量评价（验收 §三.3）

| 标准 | 评价 |
|------|------|
| 报错是否含对象名、阶段、模块 | **良好** — 启动期 `IllegalStateException` 多带类名/方法名 |
| 区分配置/资源/逻辑/同步错误 | **一般** — 未分类错误码或错误类型 |
| 日志快速定位 | **良好** — `[ytls\|framework\|module]` 前缀 + 可配置 debug |
| 静默失败 | **存在风险** — #1 导致监听无日志无异常；粒子占位可能“有调用无效果” |

## 八、建议后续工作

### 8.1 修复（建议纳入下一迭代）

1. 在 `ForgeEventBridge` 或 `LifecycleManager` 中派发 `LEVEL_LOAD` / `LEVEL_UNLOAD`（或从 `GameEventType` 移除并统一为 `WORLD_*` 生命周期）。

3. `ComponentAccess.getOrCreate` 校验 `ComponentTarget`。
4. 将 `/ytls component stats` 改为通用接口或移到 gameplay 示例命令。

### 8.2 验证（建议执行《框架测试指南》）

- `gradlew compileJava`、`gradlew runClient`、`gradlew runData`
- 单人 + LAN：`/ytls registry`、`component stats`、`skill cast`、`rule toggle`
- 组件持久化：退出重进、死亡重生（验证 #10 相关能力）

### 8.3 文档

- 在《第一优先级模块说明》中明确：`LEVEL_LOAD` 请使用 `@OnLifecycle(WORLD_LOAD)`，直至 #1 修复。
