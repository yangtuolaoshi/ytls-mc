本文描述第一优先级已落地模块的设计意图、核心类与扩展方式。对应需求文档 **10.1 第一优先级** 章节。

## 1. 启动与基础框架

### 入口

- `YtlsMod`：Forge `@Mod` 入口，仅调用 `Framework.initialize()`
- `Framework`：单例编排器，按顺序初始化配置 → 注册 → 网络 → 生命周期 → 事件

### 生命周期

- `LifecyclePhase`：语义化阶段枚举
- `LifecycleManager`：扫描 `@OnLifecycle` 并绑定 FML/Forge 事件
- 扫描根包：`icu.ytlsnb.ytls.gameplay`

### 版本抽象思路

业务层依赖 `RegistryFacade`、`NetworkPayload`、`GameEvent` 等 **接口/抽象类**。Forge 特定实现集中在：

- `ForgeRegistryProvider`
- `NetworkChannel` + `PayloadCodec`
- `ForgeEventBridge`

升级 Forge 版本时，优先替换这些实现类。

---

## 2. 注册体系

### 注解

| 注解 | 作用 |
|------|------|
| `@RegisterBlock("name")` | 自动注册方块 |
| `@RegisterItem("name")` | 自动注册物品 |
| `@RegisterEntry(kind, value)` | 通用注册入口 |

### 核心类

- `ForgeRegistryProvider`：内部 `DeferredRegister`，对外 `RegistryFacade`
- `RegistryScanner`：扫描 gameplay 包
- `RegistryAccess`：业务层静态访问入口
- `RegistryContributor`：复杂注册扩展点

### 注册目录

所有注册项记录在 `ForgeRegistryProvider.catalog()`，供数据生成读取。

### 命名规则

Registry 名必须匹配 `[a-z][a-z0-9_/]*`，重复注册会 **立即抛异常**（不静默失败）。

---

## 3. 事件体系

### 架构

```text
Forge 原始事件 → ForgeEventBridge → GameEventBus → @Listen 业务处理器
```

### 核心类

- `GameEvent` / `GameEventType`：语义事件模型
- `GameEventBus`：优先级排序、取消传播
- `@Listen`：业务订阅注解
- `ForgeEventBridge`：Forge → 框架桥接

### 扩展新事件

1. 在 `GameEventType` 增加枚举值
2. 在 `framework.event.events` 下新建事件类 extends `GameEvent`
3. 在 `ForgeEventBridge` 增加 `@SubscribeEvent` 桥接方法

---

## 4. 网络体系

### 设计

- 消息类 extends `NetworkPayload`，用 **public 字段** 承载数据
- `@NetworkMessage(id, direction)` 声明消息 ID 与方向
- `PayloadCodec` 反射编解码，业务层不接触 `FriendlyByteBuf`
- `NetworkAccess.channel()` 提供发送 API

### 方向

- `TO_SERVER`：客户端发服务端
- `TO_CLIENT`：服务端发客户端
- `BIDIRECTIONAL`：双向注册

### 安全

- 服务端处理在 `handleServer` 中通过 `ctx.sender()` 获取玩家
- 应在业务逻辑中校验权限与数据合法性（框架提供通道，校验由业务负责）

---

## 5. 同步体系

### 组件

- `@SyncField`：标记需同步的字段
- `SyncHelper.markDirty(entity, dataHolder)`：服务端推送
- `EntitySyncMessage`：内置同步消息（`framework.sync.message`）

### 当前能力

提供 **字段级字符串化同步** 的基础通道。第二优先级将结合组件系统（Capability 等）完善持久化与挂载点。

### 用法示例

```java
public class MobState {
    @SyncField
    public int rageLevel;
}

// 服务端修改后
mobState.rageLevel = 3;
SyncHelper.markDirty(entity, mobState);
```

## 6. 配置体系

### 组件

- `@ModConfig(scope, file)`：声明配置类
- `ConfigBuilder`：链式构建 `ForgeConfigSpec`
- `ConfigManager`：扫描并 `ModLoadingContext.registerConfig`

### 约定

配置类必须提供：

```java
public static final ForgeConfigSpec SPEC;
```

### 已内置配置

- `FrameworkDebugConfig` → `config/ytls-framework.toml`
- 示例 `GameplayConfig` → `config/ytls-gameplay.toml`

## 7. 资源生成体系

### 入口

`FrameworkDataGenerator` 监听 `GatherDataEvent`。

### 自动生成

| Provider | 输出 |
|----------|------|
| `AutoLangProvider` | `assets/ytls/lang/zh_cn.json` |
| `AutoBlockStateProvider` | blockstate + block model |
| `AutoItemModelProvider` | item model |

生成依据：`ForgeRegistryProvider.catalog()` 中的 BLOCK / ITEM 条目。

### 运行

```bash
gradlew runData
```

输出目录：`src/generated/resources/`（已配置为 Gradle 资源源集）。

### 限制

- 默认方块 model 为 `cubeAll`，贴图路径约定为 `textures/block/<name>.png`
- 复杂模型需手动覆盖或在后续优先级增强生成器

---

## 8. 调试体系

### 组件

- `DevEnvironment`：是否开发环境 / 调试激活
- `FrameworkDebugConfig`：运行时开关
- `DebugCommands`：`/ytls ...` 命令组

### 策略

调试命令 **默认仅开发环境或配置开启时注册**，避免污染生产环境。

---

## 9. 验收对照

| 验收项 | 实现方式 |
|--------|----------|
| 少样板代码完成基础 Mod | 注解注册 + 自动扫描 |
| 统一框架快速接入 | `Framework` 统一编排 |
| 业务不接触 Forge 底层 | 抽象接口 + 注解 |
| 资源半自动生成 | datagen providers |
| 客户端/服务端分离 | 生命周期 + NetworkDirection |
| 分支删除不影响框架 | gameplay 与 framework 物理隔离 |
