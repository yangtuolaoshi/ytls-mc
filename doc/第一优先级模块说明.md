## 1. 启动与基础框架

### 入口

- `YtlsMod`：Forge `@Mod` 入口，仅调用 `Framework.initialize()`
- `Framework`：单例编排器，按顺序初始化配置 → 注册 → 网络 → 第二优先级扫描 → 生命周期 → 事件

### 生命周期

- `LifecyclePhase`：语义化阶段枚举
- `LifecycleManager`：扫描 `@OnLifecycle` 并绑定 FML/Forge 事件
- `FrameworkReloadBridge`：配置重载、服务端数据重载时触发 `CONFIG_RELOAD` / `RESOURCE_RELOAD`
- 扫描根包：`icu.ytlsnb.ytls.gameplay`

#### 可用阶段

| 阶段 | 触发时机 |
|------|----------|
| `CONSTRUCT` | 框架构造完成 |
| `COMMON_SETUP` | FML 通用安装 |
| `CLIENT_SETUP` | 客户端安装（仅 CLIENT） |
| `DATA_GEN` | `GatherDataEvent`（`gradlew runData`） |
| `SERVER_STARTING` / `SERVER_STARTED` / `SERVER_STOPPING` | 服务端启停 |
| `SHUTDOWN` | `SERVER_STOPPING` 之后；执行 `LifecycleCleanupRegistry` 中任务 |
| `WORLD_LOAD` / `WORLD_UNLOAD` | 服务端维度加载/卸载（`@OnLifecycle`） |
| `CONFIG_RELOAD` | Forge 配置热重载 |
| `RESOURCE_RELOAD` | 服务端 `/reload` 等数据包重载 |

### 统一关闭清理

- `LifecycleCleanupRegistry`：注册关闭任务，在 `SHUTDOWN` 阶段 **逆序** 执行
- `Framework.registerCleanup(name, runnable)`：业务/子模块注册清理逻辑
- 典型用途：关闭线程池、注销临时监听器、刷新缓冲数据

维度加载有两种等价入口：

- **生命周期**：`@OnLifecycle(WORLD_LOAD)` / `WORLD_UNLOAD`（参数 `ServerLevel`）
- **语义事件**：`@Listen(LEVEL_LOAD)` / `LEVEL_UNLOAD`（`ForgeEventBridge` 桥接）

### 版本抽象思路

业务层依赖 `RegistryFacade`、`NetworkPayload`、`GameEvent` 等 **接口/抽象类**。Forge 特定实现集中在：

- `ForgeRegistryProvider`
- `NetworkChannel` + `PayloadCodec`
- `ForgeEventBridge`

升级 Forge 版本时，优先替换这些实现类。

## 2. 注册体系

### 十二类专用注解（推荐）

| 注解 | RegistryKind | 模式 |
|------|--------------|------|
| `@RegisterBlock` | BLOCK | 无参构造 |
| `@RegisterItem` | ITEM | 无参构造 |
| `@RegisterSound` | SOUND | `RegistrySupplier` |
| `@RegisterEntity` | ENTITY | `RegistrySupplier` |
| `@RegisterBlockEntity` | BLOCK_ENTITY | `RegistrySupplier` |
| `@RegisterMenu` | MENU | `RegistrySupplier` |
| `@RegisterMobEffect` | MOB_EFFECT | `RegistrySupplier` |
| `@RegisterParticle` | PARTICLE | `RegistrySupplier` |
| `@RegisterEnchantment` | ENCHANTMENT | `RegistrySupplier` |
| `@RegisterAttribute` | ATTRIBUTE | `RegistrySupplier` |
| `@RegisterCreativeTab` | CREATIVE_TAB | `RegistrySupplier` |
| `@RegisterRecipeSerializer` | RECIPE_SERIALIZER | `RegistrySupplier` |

兜底：`@RegisterEntry(kind, value)`。批量/世界生成/战利品扩展：`RegistryContributor`（见 [注册体系扩展说明.md](./注册体系扩展说明.md)）。

### 核心类

- `ForgeRegistryProvider`：内部 `DeferredRegister`，对外 `RegistryFacade`
- `RegistryScanner`：按 `RegistryKind.scanOrder()` 分阶段扫描；扫描结束输出 catalog 统计
- `RegistryAnnotationRules`：注解 → 类型/模式映射
- `RegistryAccess`：12 类快捷访问 + `resolve(kind, name)`；缺失条目明确报错
- `RegistrySupplier<T>`：复杂对象工厂接口

### 注册顺序

1. 注解类：BLOCK/ITEM → 其余（除 BLOCK_ENTITY）→ BLOCK_ENTITY  
2. `RegistryContributor` 实现类  

### 注册目录与资源关联

- `ForgeRegistryProvider.catalog()` 供 datagen 读取  
- 自动生成：BLOCK/ITEM 的 lang、model、loot、recipe、tags；CREATIVE_TAB 的 lang  

### 命名与校验

- 名称规则：`[a-z][a-z0-9_/]*`  
- **重复注册**：扫描期 `IllegalStateException`  
- **缺失条目**：`RegistryAccess.resolve` 提示添加注解或 Contributor  

### 客户端 / 服务端

注册在 Mod 构造期绑定双端；仅客户端逻辑放在 `CLIENT_SETUP`，勿在 Supplier 内直接引用客户端类。

### 示例

| 类型 | 路径 |
|------|------|
| 方块 / 物品 | `gameplay/block/ExampleBlock.java`、`gameplay/item/ExampleIngotItem.java` |
| 音效 / 效果 / 粒子 / 属性 / 创造栏 | `gameplay/registry/Example*Supplier.java` |
| 方块实体 Contributor | `gameplay/registry/ExampleGameplayRegistryContributor.java` |
| 方块实体类 | `gameplay/blockentity/ExampleBlockEntity.java` |

菜单 / 附魔 / 配方序列化器等复杂用法见 [注册体系扩展说明.md](./注册体系扩展说明.md)。

## 3. 事件体系

### 架构

```text
Forge 原始事件 → ForgeEventBridge → GameEventBus → @Listen 业务处理器
配置/资源重载 → FrameworkReloadBridge → GameEventBus + LifecycleManager
```

### 已桥接事件（GameEventType）

| 类型 | 说明 | 可取消 |
|------|------|--------|
| `PLAYER_LOGIN` / `PLAYER_LOGOUT` | 玩家登录/登出 | 否 |
| `PLAYER_TICK` | 玩家 tick（服务端 END） | 否 |
| `PLAYER_HURT` | 玩家受伤 | 是（回写 Forge） |
| `PLAYER_DEATH` | 玩家死亡 | 否 |
| `LEVEL_LOAD` / `LEVEL_UNLOAD` | 维度加载/卸载（语义事件） | 否 |
| `BLOCK_BREAK` / `BLOCK_PLACE` | 方块破坏/放置 | 是 |
| `ENTITY_SPAWN` | 实体进入世界 | 否 |
| `ENTITY_DEATH` | 生物死亡 | 否 |
| `CHUNK_LOAD` | 区块加载 | 否 |
| `DIMENSION_CHANGE` | 玩家换维度 | 否 |
| `ITEM_USE` | 右键使用物品（服务端） | 是 |
| `CONFIG_RELOAD` / `RESOURCE_RELOAD` | 配置/数据重载 | 否 |

可取消事件继承 `CancellableGameEvent`，桥接层会在 `isCancelled()` 时调用 Forge 原事件的 `setCanceled(true)`；`PLAYER_HURT` 支持修改 `amount` 并回写。

### 核心类

- `GameEvent` / `CancellableGameEvent` / `GameEventType`
- `GameEventBus`：优先级排序、取消传播
- `@Listen`：业务订阅注解
- `ForgeEventBridge`：Forge → 框架桥接

### 扩展新事件

1. 在 `GameEventType` 增加枚举值
2. 在 `framework.event.events` 下新建事件类
3. 在 `ForgeEventBridge`（或新 Bridge）增加 `@SubscribeEvent` 桥接方法

## 4. 网络体系

### 设计

- 消息类 extends `NetworkPayload`，用 **public 字段** 承载数据
- `@NetworkMessage(id, direction)` 声明消息 ID 与方向
- `PayloadCodec` 反射编解码，业务层不接触 `FriendlyByteBuf`
- `NetworkAccess.channel()` 提供发送 API

### 方向

- `TO_SERVER`：客户端发服务端
- `TO_CLIENT`：服务端发客户端
- `BIDIRECTIONAL`：双向注册

### API

- `sendToServer` / `sendToPlayer` / `sendToAllPlayers` / `sendToPlayers`

### 调试

`ytls-framework.toml` 中 `debug.logNetwork = true` 可输出网络注册与同步 debug 日志。

### 安全

- 服务端处理在 `handleServer` 中通过 `ctx.sender()` 获取玩家
- 应在业务逻辑中校验权限与数据合法性（框架提供通道，校验由业务负责）

## 5. 同步体系

### 组件

- `@SyncField`：标记需同步的字段
- `SyncHelper.markDirty(entity, ComponentType)`：**推荐**，按组件类型同步
- `SyncHelper.markDirty(entity, componentTypeId, dataHolder)`：显式指定类型 ID
- `EntitySyncMessage`：内置同步消息，客户端按 `componentTypeId` 通用分发

### 支持字段类型

`String`、`int`、`long`、`boolean`、`float`、`double`

### 用法示例

```java
@RegisterComponent(value = "mob_state", targets = {ComponentTarget.ENTITY})
public class MobStateComponent implements GameComponent {
    @SyncField
    public int rageLevel;
}

// 服务端修改后
MobStateComponent state = ComponentAccess.getOrCreate(entity, MobStateComponent.type());
state.rageLevel = 3;
SyncHelper.markDirty(entity, MobStateComponent.type());
```

## 6. 配置体系

### 组件

- `@ModConfig(scope, file)`：声明配置类
- `ConfigBuilder`：链式构建 `ForgeConfigSpec`
- `ConfigManager`：扫描并 `ModLoadingContext.registerConfig`

### 约定

配置类必须提供：

```java
public static final ForgeConfigSpec SPEC;
```

### 已内置配置

- `FrameworkDebugConfig` → `config/ytls-framework.toml`
  - `debug.enabled`：调试命令
  - `debug.logRegistry` / `logEvents` / `logNetwork`：细粒度日志
- 示例 `GameplayConfig` → `config/ytls-gameplay.toml`

### 热重载

Forge 配置重载时触发 `GameEventType.CONFIG_RELOAD` 与 `LifecyclePhase.CONFIG_RELOAD`。

## 7. 资源生成体系

### 入口

`FrameworkDataGenerator` 监听 `GatherDataEvent`，并触发 `LifecyclePhase.DATA_GEN`。

### 自动生成

| Provider | 输出 |
|----------|------|
| `AutoLangProvider` | `assets/ytls/lang/zh_cn.json` |
| `AutoBlockStateProvider` | blockstate + block model |
| `AutoItemModelProvider` | item model |
| `AutoBlockLootProvider` | 方块战利品表（掉落自身） |
| `AutoRecipeProvider` | 方块 3×3 → 物品（`example_block` → `example_ingot` 约定） |
| `AutoBlockTagProvider` | `mineable/pickaxe` 标签 |

生成依据：`ForgeRegistryProvider.catalog()` 中的 BLOCK / ITEM 等条目。

### 运行

```bash
gradlew runData
```

输出目录：`src/generated/resources/`（已配置为 Gradle 资源源集）。

### 限制

- 默认方块 model 为 `cubeAll`，贴图路径约定为 `textures/block/<name>.png`
- 配方自动生成遵循命名约定（`*_block` + `*_ingot`），其它组合需手写或 `RegistryContributor`

## 8. 调试体系

### 组件

- `DevEnvironment`：是否开发环境 / 调试激活
- `FrameworkDebugConfig`：运行时开关与日志细项
- `DebugCommands`：`/ytls ...` 命令组

### 命令

| 命令 | 说明 |
|------|------|
| `/ytls debug` | 确认调试模式 |
| `/ytls registry` | 按 RegistryKind 统计注册数量 |
| `/ytls reload-config` | 配置重载说明 |
| `/ytls skill cast <id>` | 技能测试（第二优先级） |
| `/ytls rule toggle <id>` | 世界规则开关（第二优先级） |
| `/ytls component stats` | 组件读写 + **同步到客户端** |

### 策略

调试命令 **默认仅开发环境或配置开启时注册**，避免污染生产环境。

## 9. 验收对照

| 验收项 | 实现方式 |
|--------|----------|
| 少样板代码完成基础 Mod | 注解注册 + 自动扫描 |
| 统一框架快速接入 | `Framework` 统一编排 |
| 业务不接触 Forge 底层 | 抽象接口 + 注解 |
| 资源半自动生成 | lang / model / loot / recipe / tag |
| 客户端/服务端分离 | 生命周期 + NetworkDirection |
| 分支删除不影响框架 | gameplay 与 framework 物理隔离 |
| 事件覆盖常见玩法 | 15+ 语义事件 + 可取消回写 |
| 组件字段同步 | 通用 `componentTypeId` 协议 |
